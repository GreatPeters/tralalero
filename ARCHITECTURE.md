## Forward Enemy Events

- The six Forward enemy prefab roots carry `EnemyEventController`. Each instance selects exactly one triggered mode: repeat its attack, attack once then idle, shoot once, move to one target and then repeat its attack, or patrol between its authored start and one target while playing `attack_once` at both endpoints. Movement animation independently selects none (looping idle), walk, or run.
- The Noryangjin map tool automatically aligns a Forward enemy placed from the enemy palette to the player's travel direction at that map position. It resolves the nearest route section from the player's authored start transform and the turn spots, while preserving each section's exact initial/outgoing direction instead of using a slightly diagonal line between offset trigger centers. The placement preview uses the same result; selected and all-enemy alignment buttons repair existing placements. Copy placement deliberately preserves the source instance rotation so manual encounter overrides remain reusable. If the scene has no player route, the authored palette Y rotation is retained, and every placed enemy can still be rotated manually afterward.
- Movement modes use one external target `Transform`; the Inspector and map-tool selected-enemy card can create it with `이동 목표 만들기`, and the Scene handle edits that single point.
- `EnemyEventActivationSpot` is a rendererless player-root `BoxCollider` trigger. It serializes only linked enemies—there is no `oneShot`/`on shot` option—and disables after any linked event accepts activation. It resets for the next run.
- The map-tool palette exposes the spot as `적 발동 스팟`. Selecting it makes it the active SceneView mapping owner: enemy clicks toggle links, connection lines show the result, and `Esc` clears the spot selection. Event mode and target remain owned by each enemy.
- `EnemyEventController` delays first placement capture until its first runtime update because pooled enemies are enabled before `EnemySpawnerScript` assigns the final spawn transform. Re-enabling a scene-authored enemy preserves and restores its captured start; re-enabling an enemy while it is still parented under `EnemyPooler` deliberately requests a fresh post-spawn capture.
- Map-tool position, snap, height, and rotation edits notify an initialized `EnemyEventController`. Its cached start and route axes therefore follow `한 칸 이동`, Undo/Redo, and other authoring changes.
- `GameManager.OnTapToPlay` resets active event controllers and consumed activation spots before gameplay resumes.
- Triggered projectile delay advances only while gameplay and the time factor advance. Zero-speed movement is rejected; destroyed targets cancel to idle once. Legacy mode 3 normalizes to move-then-attack. Idle previews preserve authored rotation; movement/attacks use explicit mesh-forward correction, not the placement's idle half-turn.
- `ForwardEnemyMovementSetup.Configure` remains an internal repair API for the six default prefab components and the trigger prefab. It is not exposed in the map-production menu and does not save an open scene.
