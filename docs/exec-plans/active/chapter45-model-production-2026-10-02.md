## 생성과 적용 규칙

1. 위 순서대로 후보의 기존 납품본·입력·현재 화면을 비교한다. 합격한 기존 모델은 재생성하지 않는다. 신규가 확정된 B02–B04와 필요시 B01을 다음 순차 생성 대기열로 삼는다. 현재 식물은 완료된 생성을 재실행하지 않는다.
2. 생산 해상도는 기존 성공 기록의1536 경로(초기 shape1024/격자64→1536 cascade, 중간300k, shape12/texture25/2K)를 기준으로 한다. 설치된 사용자1536 설정을 바꾸지 않고 요청 JSON에만 기록한다. 512는 정상 격자32의 복구 시험에 한정해 성공했으며, 모든 딱딱한 목재 모델의 품질을 보증하지 않는다.
3. GPU 생성은 한 번에 한 작업만 진행한다. Unity 성능 비교 중에는 새 GPU 생성 작업을 돌리지 않는다. 캐시·정확한 prompt ID를 기록하고 타임아웃을 자동 재제출하지 않는다.
4. 원형→간소화→텍스처→내보내기→Unity를 구분한다. 단계별 파일/해시를 남기고 결함이면 마지막 정상 단계로 돌아간다. 무조건 더 생성하지 않는다. 1차와 근거 있는 수정1회 뒤에도 불합격이면 해당 항목만 차단으로 보고하고 다른 항목을 진행한다.
5. 원본2K와 고밀도 메시를 납품/검증 폴더에 보관한다. 게임에는1K 기본, 모바일 ASTC6x6·밉맵·read/write off, 공유 재질을 사용한다. 변형마다2K를 추가하지 않는다. 멀리 보이는 반복 상품은 LOD/표시 범위/인스턴스 수를 더 줄인다.
6. 콜라이더0인 장식으로 적용하고 사람 크기의 실측 치수·바닥/상판 피벗을 맞춘다. FBX의 축변환 회전을 보존한다. 기존 경기·동선·저장·보상·리프트·선택 UI·인트로 목적지를 보호한다.
7. 각 묶음은 같은 카메라 전후와 실제 플레이 캡처를 만든다. 독립 아트 검토와 두 선택 경로, 보스·리프트, 공유 자산208개 해시/최소복구본/선호값 복원 검증을 분리해 기록한다. 모바일 실제 FPS는 기기 검증 전까지 미검증으로 남긴다.
8. 새 입력 이미지가 필요하면 기존 로컬 정식 입력부터 조사한다. 적합한 자료가 없으면 무료·공개 출처 또는 사용자가 이미 제공한 이미지를 검토하고 출처를 기록한다. 유료 이미지 생성·새 계정·설치·외부 업로드를 임의로 시작하지 않는다.
9. Meshy는 이번 지시로 결제가 승인된 것이 아니다. 필요성이 확정된 캐릭터만 기존 키의 지원된 경로로 가격/잔액을 읽기 전용 확인하고 예상크레딧과 총한도를 별도 보고한다. 비밀값은 출력·기록하지 않는다.
