# 휴게소 Blender 300초 · 연결된 10구간

## 사용자 요청

- PPT 진입 사진과 직전 휴게소 콘셉트를 바탕으로 하나의 큰 환경을 Blender에 제작한다.
- 순서: 진입 → 주차 → 본관 앞 휴식 → 건물 입구 → 진입 직후 개활지 → 식당 → 편의점 → 옆 화장실 → 주유소 → 주유소 출구.
- 전체 300초 애니메이션과 각 구간 영상 10개를 제공한다.
- 5구간은 탑뷰·플레이어 위치 고정·사방의 적 방어 60초. 조준 회전은 계단식 90도가 아니라 최대 90도/초, 즉 0.1초당 최대 9도다.
- 화장실을 앞 시안보다 5배 크게 만든다. 면적 약 5배로 해석하며 선형 치수 5배(면적25배)로 확대하지 않는다.
- 어울리는 사람 시안과 편의점 시안을 새로 그린다. 적과 재미있는 기믹을 배치하고 실제 움직임을 보여준다.
- 이번 작업은 Blender 제작·애니메이션이다. TRELLIS 실행, Seedance 제작, Unity 설치는 범위에 없다.

## 제작 계약 / 에이전트 선택

|구간|시간|길이|연출|
|---|---|---:|---|
|01 진입|0–25|25s|PPT의 휴게소 분기·표지, 커브, 차단기|
|02 주차|25–50|25s|주차 차량 사이 진행, 후진 차량 예고·회피|
|03 앞마당|50–75|25s|벤치·식재·간식 매대, 사람들 도망과 카트|
|04 입구|75–100|25s|넓은 유리문, 자동문 열림, 내부로 카메라 전환|
|05 개활지 방어|100–160|60s|고정 탑뷰, 제자리 90도/초 이하 연속 회전, 사방 접근|
|06 식당|160–190|30s|테이블·주문대, 이동 카트와 음식 투척 예고|
|07 편의점|190–220|30s|진열 선반·냉장고·카운터, 가로지르는 상품 카트|

|09 주유소|250–275|25s|기둥·캐노피·주유기·호스, 차량 통과와 안전한 회피|
|10 출구|275–300|25s|출구 차단기·합류 차선, 마지막 추격·통과|

Blender 5.2.1 LTS를 사용한다. 기존 프로젝트 상어 에셋의 형태를 유지하고, 인물은 직접 제작하는 스타일 캐릭터 또는 기존 로컬 리그를 검토 후 재사용한다. 신규 외부 3D 생성은 하지 않는다. 환경은 낮은 장방형 본관, 황토색 지붕선, 목재 매대, 투명 아치 캐노피, 크림색 석재, 빨간 주유소 지붕으로 묶는다.

300초를 실제 타임라인으로 제작하며, 영상 이어붙이기로 공간의 불연속을 숨기지 않는다. 하나의 마스터 씬과 연속된 플레이어 이동을 사용하고, 10개 클립은 같은 마스터의 정확한 시간 구간이다. 애니메이션 FPS·해상도는 실제 로컬 렌더 시간과 시각 품질을 측정해 결정한다. 프리비즈의 카메라 가림 방지를 위한 지붕 표시 처리는 명시한다.

## 단계

1. 계약·레퍼런스·신규 이미지: 완료. 사람8종, 편의점2D콘셉트 보관.
2. 전체 배치·동선: 완료. 편의점/화장실 바닥 연결과 화장실/주유소 보도 보강.
3. 주요 건축 형태, 시설, 캐릭터와 연결 구조: 완료.
4. 재질·카메라·애니메이션: 완료. 원본 상어형상 유지, 나머지 직접 모델링.
5. 구간별 정지화면·회전 제한 검증: 통과. 실제 네이티브24fps,7,200프레임,방어1,441프레임 표본 검사. 부동소수점 허용차0.01도/초 명시.
6. 전체300초·구간10개 렌더/인코딩: 완료. 최종1,280×720,24fps EEVEE.10개 클립 전체 디코드와300초 통합본7,200프레임의 순서별 해시 일치까지 통과했다.
7. 최종 원본·환경GLB 재임포트·모든 구간의 추출 프레임·인물8종·브라우저 갤러리 검토 완료. 최종보고는`map-concepts/reststop-blender-300s-2026-09-23/final_report.md`.

## 실행 및 수정 기록

- FBX 가져오기가fps를30으로 바꾼 것을 저장본 검증이 발견했다. 가져오기 뒤24fps를 재설정하고 다시 검증했다.
- 공유 primitive 메시를 합치는 활성 객체의 데이터 소유권 문제를 수정했다. 초기11,413,746삼각형이 동등한 장면에서832,086으로 정상화됐다. 이후 경찰32명 등 추가된 장면은약88만이다.
- 최초 주유소 지붕 가림, 입구 간판 가림, 너무 가까운 탑뷰, EEVEE투명 노이즈를 수정했다.
- 영상 검토로 경로 모서리의Euler각도랩과 첫 피격 효과의 반 프레임 키 충돌을 발견했다. 수정한 시점은`route-turn-patch.json`에 기록했다.
- 작업 소유 렌더러만 중단해3,790개 완전한JPEG를 보존했다. 손상된 꼬리JPEG는없었다. 앞부분779프레임을 보강된 마스터로 다시 렌더하고, 뒤쪽은 같은 수정본에서 이어 촬영한다.
- `finish.py`는수정렌더완료 → 나머지프레임 → 기존인코더완료 → 앞4개최종인코딩 → 네이티브검증/GLB → 재임포트/뷰/인물 → 영상검토용프레임 → 갤러리 순서로 실행한다. 마지막`ready_for_visual_review`를실제완료로취급하지말고이미지를열어검토해야한다.
- 현재 실행 중인`finish.py`는 최종 정지화면 재생성 호출을 추가하기 전 로드됐다. 파이프라인이 끝난 뒤`render.py --mode evidence --width1280 --samples16`을 한 번 별도로 실행해 정지화면도 최종 마스터와 맞춘다.
- ZIP은 영상·갤러리 최종 시각 검토 뒤`package.py`로 작성한다. 최종 문서의 상태와 실측 메시 개수를 갱신한 뒤 전달한다.
- 완성된8구간 영상에서 전면 벽이 상어를 오래 가리는 문제가 추가 확인됐다. `refine_restroom_camera.py`로215–253초의 카메라만 더 가파르게 내려다보도록 고쳤다.6개 시점의 카메라→상어 몸통 광선 검사가 통과했다. `final_camera_pass.py`가 기본 파이프라인 종료를 기다린 뒤 최종 정지화면과 해당911프레임을 렌더하고7·8·9구간을 다시 인코딩한다. 최종 대기 상태는`camera-pass-state.json`의`ready_for_final_review`다.
- 최종 검토에서 정적인 직원의 다리가 환경 배치에 합쳐진 소유권 문제를 고쳤다. `restore_actor_ownership.py`가6명의 다리를 각각의 관절에 복구했고,3,696삼각형 수와 정점 위치(최대오차0.000018m 미만)가 보존됐다. 이후 환경GLB는 모든 인물 하위 요소를 제외한다.
- 새 화장실 카메라가 공용 통로를 막던 불필요한 칸막이를 드러냈다. `clear_restroom_aisle.py`로해당성분만제거하고, `check_indoor_aisle.py`로190–253초의 정적 중심 동선을 검사한다. 마지막 재촬영은`restroom-final-patch.json`의1,512프레임이며, `final_camera_pass.py --patch-file restroom-final-patch.json --finalize-assets`가영상·모델·인물뷰·갤러리를함께갱신한다. 이전911프레임 패스는 최종 전달본이 아니다.

## 검증 기준

- 단일 마스터 파일, 10개 순서와 총300초/방어60초가 수치로 일치한다.
- 방어전 동안 플레이어 XY가 고정, 프레임별 yaw 속도가90도/초 이하이고 실제 사분면 전체를 조준한다.
- 문, 후진차, 카트와 적이 정적 소품이 아니라 실제 시간에 따라 움직인다.
- 구간 경계에서 플레이어 위치가 이어지고, 실내 통로가 벽·선반을 관통하지 않는다.
- 각 구간의 건축과 기믹을 실제 Blender 렌더에서 확인한다. 생성 이미지나 콘셉트를 렌더 증거로 대신하지 않는다.
- 렌더는 작업 소유 프로세스만 낮은 우선순위/스레드 상한을 적용한다. Unity 상태와 다른 작업은 보존한다.
