# 노량진 게임플레이 및 회전 스팟 작업 가이드

## Forward 구성 확인

1. Unity에서 `Assets/ShooterSurvival/Scenes/Tools/Noryangjin_MapTool_Mode.unity`를 연다.
2. `Tools/맵 제작 도구/노량진 맵 제작/맵툴 열기`로 맵툴을 연다.
3. 씬을 연 뒤 `Noryangjin_Player` 아래에 기존 `Original` 캐릭터가 유지되는지 확인한다. `Original`을 분리하거나 Forward에서 복제된 숨김 비주얼을 다시 켜지 않는다.
4. Build Settings에서 `Noryangjin_MapTool_Mode`가 활성화된 index `0`, `Forward March Mode`가 활성화된 index `1`인지 확인한다.

Forward 설치기는 이미 구성된 씬의 내부 복구 API로 유지되며 맵 제작 메뉴에는 노출하지 않는다.

내부 설치기는 Forward 씬에 실제로 설정된 플레이어·무기 리그, 시작 전 UI와 상점 UI, Managers, EventSystem, 업그레이드 서비스를 노량진 씬에 연결한다. 노량진 맵의 캐릭터 외형과 카메라는 유지하며, 실행에 필요한 동작과 UI만 Forward 구성에 맞춘다.

## 플레이어 상태 HUD

내부 Forward 설치기는 `PlayerStatusHUD`도 함께 생성하고 검증한다. HUD는 화면 왼쪽 위의 반투명 다크 글래스 카드 두 장으로 구성되며, 흰색 텍스트와 코랄 체력 게이지를 사용한다. 위 카드는 현재/최대 체력과 게이지를, 더 짧은 아래 카드는 현재 공격력을 표시한다. 게임 시작 전에는 숨겨지고 시작 후 활성화되며, 체력·공격력 업그레이드와 피해를 실제 런타임 값으로 반영한다. HUD가 정상 구성된 경우에만 기존 플레이어 머리 위 체력 Canvas와 `ATT` 디버그 텍스트를 숨긴다.

HUD만 다시 만들 때는 Play Mode를 끄고 노량진 맵1 씬을 연 뒤 `Tools/Shooter Survival/UI/Apply Player Status HUD`를 실행한다. 이 명령은 기존 `PlayerStatusHUD` 루트만 교체하므로 다른 씬 오브젝트를 건드리지 않으며 반복 실행할 수 있다. 현재 다크 글래스 디자인의 실제 플레이 캡처는 `Assets/ShooterSurvival/UI/References/Editor/PlayerStatusHud_DarkGlass_Reference.png`, 이전 양피지 시안은 같은 폴더의 `PlayerStatusHud_SlimCards_Reference.png`, 런타임 하트 아이콘은 `Assets/ShooterSurvival/UI/PlayerStatus/PlayerStatus_Heart.png`에 보존된다.

`Noryangjin_MapTool_Mode_2.unity`에는 복제 시점의 동일한 게임플레이 구성이 들어 있지만, 내부 설치기 대상이나 Build Settings 항목은 아니다. 맵2는 설계도 구현을 검토하는 정적 씬으로 유지하고, 실제 런타임 시간·웨이브 계약이 확정되기 전에는 맵1용 설치기를 억지로 적용하지 않는다.

## 전진 이동 속도

- `Data.xlsx`의 `환경 변수 > playerSpeed > 값1`이 전진 속도의 단일 설정값이다.
- 실행 중 시간 경과에 따른 가속은 없으며, `playerSpeed`의 값2와 값3은 사용하지 않는다.

## 현재 배치 정보

맵툴의 `보너스` 오른쪽에 있는 `정보` 탭은 현재 열린 씬의 배치 수량을 보여 준다.

- `길`은 기본길, 내리막길, 다리, 오르막길, 우회전길, 좌회전길을 각각 표시하고 `길 총합`을 함께 표시한다.
- `오브젝트`는 `Noryangjin_MapTool/Props` 바로 아래의 배치 루트를 팔레트 표시 이름별로 묶어 수량을 표시하고 `오브젝트 총합`을 함께 표시한다.
- 오르막길·내리막길에 붙는 기둥이나 일반 프리팹의 자식은 별도 배치로 중복 집계하지 않는다.
- 오브젝트 추가·삭제와 Undo/Redo로 하이어라키가 바뀌면 집계 캐시가 무효화된다. 즉시 다시 확인하려면 `새로고침`을 누른다.

## 회전 스팟 배치

1. `Tools/맵 제작 도구/노량진 맵 제작/맵툴 열기`를 연다.
2. 팔레트에서 `회전 스팟`(↻)을 선택하고 캐릭터가 코너에 진입할 때 반드시 통과하도록 길을 가로질러 배치한다.
3. 선택 모드에서 배치한 회전 스팟의 핫핑크 트리거 영역 아무 곳이나 눌러 선택한다.
4. `설치 조정`에서 스팟 자체의 위치와 설치 방향을 맞춘다. 설치 방향은 트리거가 길을 가로지르는 범위를 정하는 값이며 캐릭터의 최종 방향과는 별개다.
5. `회전 스팟 동작`에서 `목표 X 회전`, `목표 Y 회전`, `회전 시간(초)`을 정한다. `-45도`/`+45도`는 목표 Y 회전에 적용되고, `0.25초`/`0.5초`/`1초` 빠른 설정도 사용할 수 있다.

`목표 X 회전`과 `목표 Y 회전`은 현재 각도에 더하는 값이 아니라 절대 월드 각도다. 평평한 길에서는 X를 `0°`로 두고 Y로 진행 방향을 정한다.

- `0°`: 월드 `+Z`
- `90°`: 월드 `+X`
- `180°`: 월드 `-Z`
- `270°`: 월드 `-X`

노량진 맵툴 Scene 뷰에서는 배치한 모든 스팟이 핫핑크 트리거 영역과 검은 외곽선이 있는 노란 방향 화살표, 목표 X/Y 각도로 항상 표시된다. 선택한 스팟은 더 굵은 화살표와 회전 시간까지 포함한 라벨로 강조된다. 이 표시는 맵툴 에디터 전용이라 실제 게임 화면에는 나오지 않는다.

## 런타임 동작

플레이어의 루트 이동 콜라이더가 스팟에 들어오면 다음 순서로 동작한다.

1. 앞으로 이동과 좌우 터치 입력을 멈춘다.
2. 현재 위치를 유지하며 설정 시간 동안 목표 월드 X/Y 각도로 부드럽게 회전한다.
3. 회전이 끝나면 새 방향을 로컬 전방으로 삼아 자동 이동과 좌우 입력을 재개한다.

공격 스케줄은 회전 중에도 유지된다. 회전 전에 발사되어 비행 중인 플레이어 미사일도 캐릭터의 프레임별 회전량만큼 진행 방향과 자세가 함께 꺾이므로 코너를 따라 곡선으로 나간다. 이때 미사일 속도와 남은 지속시간은 바뀌지 않으며, 적이나 동료가 발사한 투사체는 영향을 받지 않는다. 회전 요청이 성공한 스팟은 즉시 비활성화되어 같은 플레이에서 다시 작동하지 않고, 다음 플레이를 시작할 때 다시 활성화된다. 한 코너에는 진입 경로에서 한 번만 통과하는 스팟 하나를 사용하고, 경로가 다시 꺾일 때마다 별도의 회전 스팟을 배치한다.

자동 전진은 기울어진 전방 벡터를 바닥면에 투영하므로 X 회전으로 캐릭터가 공중으로 이동하지 않는다. 다만 X가 `90°` 또는 `-90°`에 가까우면 수평 전방 성분이 거의 없어 자동 전진도 거의 멈춘다.

## 기믹 장애물 배치

맵툴의 `기믹` 탭은 `Assets/ShooterSurvival/Prefabs/Obstacle/ObstaclePrefabs.asset`에 등록된 실제 게임용 장애물 목록을 그대로 사용한다. 현재 구멍, 기름, 배, 조명, 보트, 돌고래, 양동이, 갈매기 8종이 각각 한 번씩 표시된다. `Boat`, `Oil`, `Bucket`, `Seagull`처럼 복합 장애물을 구성하는 단일 부품 프리팹은 중복 노출하지 않는다.

장애물을 추가하거나 교체할 때는 폴더를 별도로 스캔하게 만들지 말고 `ObstaclePrefabs.asset`의 `obstaclePrefabs` 목록을 갱신한다. 맵툴 창을 다시 열면 같은 목록이 기믹 팔레트에 반영되며, 선택한 장애물은 일반 맵툴 오브젝트처럼 위치·회전·크기와 풋프린트를 조정해 배치할 수 있다.

## 보너스 제단 배치

1. 맵툴의 `보너스` 탭에서 `운명의 제단` 하나를 선택한다.
2. `설치 조정`의 `제단 다음 배치 등급`에서 `노멀`, `엘리트`, `유니크` 중 하나를 고른 뒤 배치한다.
3. 이미 배치한 제단은 하이어라키에서 선택하고 같은 카드의 `제단 등급`, 또는 루트 `AuthoredBonusWall` Inspector의 `제단 등급`으로 변경한다.

제단 외형 프리팹은 `Box_left.prefab` 하나만 사용한다. 등급은 외형 종류가 아니라 런타임 후보군을 정한다. `노멀`은 `Data.xlsx > 보너스`의 `Normal`, `엘리트`는 `Rare`, `유니크`는 `Unique` 행을 사용한다. 표시 이름은 `이름`, 실제 효과는 `항목`, 랜덤 수치는 `최소`/`최대`에서 읽는다. 선택 제목은 표시 이름 뒤에 `강화`를 붙여 `체력 강화`, `공격력 강화`처럼 일관되게 표시하며, `별칭`은 데이터 행의 기획용 표현으로 유지한다. `수치 타입`이 `Percent`인 행만 값 뒤에 `%`를 표시한다. `attPercent`/`hpPercent`는 같은 등급의 `att`/`hp` 행 이름과 일반 공격/체력 아이콘을 사용하므로, 이름은 `공격력`/`체력`으로 통일되고 접미사만 수치 타입으로 구분된다.

노멀과 엘리트 제단은 굴려진 능력 계열에 맞춰 공격·공격속도는 호박색, 체력은 청록색, 투사체·동료 계열은 바다색으로 워프·에너지 빔·배지 외곽선·수치를 함께 바꾼다. UI는 큰 수치를 위에 두고 그 아래에 작은 아이콘과 능력명 배지를 둔다. 수치와 라벨 TMP는 독립적으로 자동 축소되며 `+999`, `+11%`, `ATK SPEED`까지 한 줄로 표시한다. 바닥 워프는 바깥 물결, 반대 방향으로 도는 안쪽 물결, 희소한 컴퍼스 링, 정방향 포말의 네 레이어와 안쪽으로 말려 올라가는 물방울로 구성한다. 플레이어가 접근하면 가까운 제단만 워프·에너지·수치·배지가 부드럽게 커져 선택 예정 방향을 보여 준다. 유니크 제단은 능력치 종류와 관계없이 같은 효과를 보라색으로 통일하고, 효과 크기와 파티클 밀도를 높이며 회전과 펄스도 빠르게 한다. 이 변화는 런타임 인스턴스에만 적용되므로 하이어라키에서 등급을 바꿔도 공유 Material이나 프리팹·씬의 기준 Transform, 파티클, 색상 값은 변경되지 않는다.

Forward 적이 사망할 때도 레거시 `random_wall_normal` 대신 같은 `Box_left` 운명의 제단을 적의 지면 위치에 생성한다. 이때 맵툴 배치 결과와 같은 최종 크기 `(3, 3, 3)` 및 Y 회전 `180°`를 적용한다. 적 드롭은 프리팹 기본 등급인 노멀로 굴리고 `RuntimeBonusWall`로 표시하므로, 다음 스테이지 준비 시 제거되지만 맵툴에서 직접 배치한 제단은 유지된다.

가까운 제단은 XZ 평면의 `인접 판정 거리`로 묶이며 기본값은 12다. 먼저 결정된 제단의 능력치 키를 다음 제단의 후보에서 제외하므로 좌우로 붙인 두 제단은 서로 같은 능력을 제시하지 않는다. 등급 후보가 바뀌어도 동일한 키(`att`, `hp` 등)는 중복으로 취급한다.

프리팹을 다시 만들 때는 `Tools/Shooter Survival/Bonus Choice Boxes/Build Box Prefabs`를 실행한다. 과거 `Box_Right` 인스턴스가 남은 열린 씬은 `Tools/Shooter Survival/Bonus Choice Boxes/Migrate Open Scene To Single Altar`로 위치·회전·크기·등급을 유지한 채 단일 프리팹으로 교체한다.

이미 배치된 `Box_left`가 생성 UI/VFX 자식 오버라이드를 가지고 있어 새 프리팹 외형을 상속하지 않을 때는 `Tools/Shooter Survival/Bonus Choice Boxes/Refresh Open Scene Altar Instances`를 실행한다. 루트 위치·회전·크기·이름·등급은 유지하고 생성 자식만 최신 프리팹으로 교체한다.

## Play Mode 확인

- 시작 전 UI와 상점 UI가 Forward 씬과 같은 흐름으로 보이는가
- Start 이후 캐릭터가 현재 바라보는 방향으로 이동하고 공격하는가
- 코너에서 이동이 잠시 멈추고 설정한 시간과 절대 각도로 회전하는가
- 코너 진입 전에 발사한 플레이어 미사일이 캐릭터와 같은 각도로 부드럽게 꺾이며 속도·지속시간을 유지하는가
- 회전 후 새 전방으로 이동하며 좌우 입력도 새 경로의 오른쪽/왼쪽을 따르는가
- `기믹` 탭에 설정된 장애물 8종이 중복 없이 보이고 선택·배치되는가
- 실제 `Original` 외형은 보이고 복제된 Forward 캐릭터 외형은 숨겨져 있는가
- 가까이 배치한 제단 두 개가 서로 다른 능력과 각 행 범위 안의 수치를 보여 주는가

필수 서비스가 일부만 있거나 `Original` 또는 카메라를 찾지 못하면 설치는 저장하지 않고 오류를 남긴다. 이 경우 임의로 중복 오브젝트를 만들지 말고 Console의 누락 항목을 먼저 복구한 뒤 설치 명령을 다시 실행한다.
