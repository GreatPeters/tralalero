## 실측 차단과 남은 작업

기기는 `showing=true`, `mWakefulness=Dozing`이었다. 사용자 잠금 해제를 요청했고 아직 확인되지 않았다. 화면을 켜는 입력만 보냈으며 잠금해제/보안설정을 우회하지 않았다. 기존 게임 실행 프로세스는 확인했지만 전면 앱이 아니므로 스크린샷 가드가 다른 화면 캡처를 차단했다. 이 실행을 실제 게임 화면 검증으로 세지 않는다.

**실제 휴대폰 FPS·프레임 스파이크·로딩·PSS메모리·앱 네트워크 요청 시간은 측정0건이다. 핑이나60FPS통과,기기 최적화 완료를 주장하지 않는다.** 배터리 시작 조건만 USB충전/70%/약30.4°C로 기록했다. Editor프레임이나 잠긴 상태의 백그라운드15FPS를 모바일 성능으로 바꾸어 보고하지 않는다.

1. 그 사이 생길 수 있는 사용자 플레이 진행을 보호하도록 **새 휴대폰 저장 기준본**을 먼저 확보한다. 이번28키를 그대로 다시 덮어써서는 안 된다.
2. 보존한 동일서명 진단 APK로 업데이트하고 새 기준본을 확보한 후,개발용 로컬 표식을 명시적으로 활성화한다. 진단은 허용된5씬 로드·입력·계측만 수행하고 release에는 없다.

4. 게임의 실제 네트워크 사용은 Firebase 분석/보상광고 SDK이며 실시간 대전 서버나 전투 ping API는 발견되지 않았다. 기존 테스트광고 SDK의 요청→콜백 시간/준비 상태를 관찰하도록 준비했다. 임의 서버 ping을 게임 지연으로 보고하지 않는다. 광고를 보여주거나 구매할 필요는 없다.
5. 관측된 병목만 개선해 같은 조건으로 재검증하고,새 저장 기준본 복원 후 일반 APK로 되돌려 최종 설치본을 검증한다.

## 15:00 UTC 잠금 해제 후 재개 결과

사용자가 “풀었어”라고 알려 준 뒤 15:02 UTC에 같은 S22의 `showing=false`, `inputRestricted=false`, `Awake`를 확인했다. 준비 중 다시 보안 잠금 상태로 바뀌었으며, 잠금 상태에서는 플레이 입력과 화면 캡처를 보내지 않았다. 화면 깨우기 입력 한 번만 보냈고 인증·잠금 해제 제스처·보안 설정 변경은 하지 않았다.

독립적으로 가능한 준비는 완료했다. 동일 서명 `diagnostic-r1`을 데이터 유지 업데이트하고 **15:10:38 UTC의 새 저장 기준본**을 첫 진단 실행 전에 확보했다. 이전 기준본을 덮어쓰거나 사용자의 중간 진행을 과거 값으로 되돌리지 않았다. 현재 저장은 게임 28키와 엔진 4키, 코인 167·보석 0이었다. 앱 부트스트랩과 진단 상태 읽기는 실제 휴대폰에서 확인했다. 화면 잠금 뒤의 프레임 텔레메트리는 게임 플레이 성능으로 채택하지 않았다.

잠금 해제를 최대 5분 관찰하고 확인 즉시 Ch1 플레이를 시작하도록 준비했으나 `showing=true`, `secure=true`가 유지되어 타임아웃됐다. 새 게임 시작·이동·씬 이동 입력은 0건이고, 허용된 진단 요청은 상태 읽기뿐이었다. 따라서 **실제 전경 플레이, 유효 FPS 측정창, 프레임 스파이크·로딩·PSS·게임 통신 지연 측정은 여전히 0건**이다. 휴대폰이 느리다는 근거 없이 최적화를 임의로 적용하지 않았다.

재개 종료 시 이번 새 기준본의 게임 28키를 타입·값까지 정확히 복원하고 현재 엔진 9키를 보존했다. 최초 4키에 진단 앱 실행으로 Unity가 자연 생성한 세션 관련 5키가 추가됐으며, 복구 도구는 이 엔진 키를 삭제하거나 값을 바꾸지 않았다. 진단 표식을 비활성화한 후 다시 일반 `release-r1` APK로 업데이트했다. 설치 APK SHA-256은 `fd4795658cbd09f6c48512092a9612ca67bc52108b73e4c101441b1e1f25f34b`로 일치하고, 비디버그 상태·진단 타입 부재·앱 데이터 inode·최초 설치 시각 유지도 확인했다. 일반 APK로 돌려놓은 상태를 실제 플레이 완료로 표현하지 않는다.

새 증거는 `outputs/s22-device-validation-2026-10-05/`에 있다.
