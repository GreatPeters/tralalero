# Bonus Wall 로컬 이미지 갤러리

2026-09-19. 사용자가 Codex 탭의 이미지 클릭 후 빈 화면이 나타나는 스크린샷을 제공했다. 동일한 로컬 PNG 링크를 반복 제시하는 것만으로는 열람 문제가 해결되지 않았다.

## 제공한 우회 경로

- `tmp/image-previews/bonus-gallery-2026-09-19/index.html`: 단독 HTML 갤러리와 상대경로 PNG 사본 33개.
- 최신 맥락 시안 3, 프리팹 활용 10, 신성한 제단 10, 초기 효과 10.
- 이미지 클릭 확대, 화면에 맞춤/원본 크기, 이전/다음, PNG 링크/다운로드.
- 서버는 `127.0.0.1`의 OS 할당 포트에만 바인딩하고 이 갤러리 폴더만 제공한다. 프로젝트 전체를 제공하지 않는다.
- 실행 시 현재 URL을 갤러리 폴더의 `server.json`에 기록한다. 이번 실행 URL은 `http://127.0.0.1:6753/`, PID는 `server.pid`에 기록했다.
- PC/서버 재시작 후에는 현재 URL이 달라질 수 있다. 갤러리 폴더의 index.html은 탐색기에서 브라우저로 직접 열어도 사용할 수 있다.

## 재생성 및 실행

프로젝트 루트에서:

```powershell
python map-concepts/bonus-gallery-2026-09-19/build.py
python map-concepts/bonus-gallery-2026-09-19/serve.py
```

자동화에서 서버를 실행할 때는 숨겨진 프로세스로 시작한다. 불필요한 중복 서버를 실행하지 않고 기존 server.json URL의 가용성을 먼저 확인한다.

## 확인

- 최신 원본 3개는 System.Drawing으로 정상 디코딩, 1536×1024.
- 갤러리 빌드에서 요청 파일 33개의 사본 생성.
- Chrome에서 실제 썸네일/확대 화면을 스크린샷으로 확인하고 다음 이미지 및 원본 크기 전환을 실행했다.
- 첫 갤러리에서 HTML img height 속성이 과도한 높이를 유지했다. 반응형 CSS에 height:auto를 추가하고 다시 스크린샷으로 확인했다.
- Chrome 탭은 사용자 열람용 deliverable로 보존했다.
- 설치된 Edge는 브라우저 자동화 연결에 없었고, 연결된 Chrome을 사용했다. 앱 내부 이미지 뷰어의 정확한 원인 또는 복구를 확인한 것은 아니다. 공식 문제 해결 문서 검색에서도 이 특정 빈 이미지 화면의 원인을 확정하지 못했다.
