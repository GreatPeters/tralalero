# 휴게소 소품·인물 TRELLIS 제작 계약

2026-09-24 사용자 요청: 기존 TRELLIS2.0 자동화의 예전 저장값으로 소품을 만들고 사람에는 본과 애니메이션을 추가한다.

## 범위와 산출물

- 기존 검토된 단독 PNG 69종 + 원본 Blender 대조로 찾은 환경 형태 7종 + 인물 장비 6종 = 소품/구조/차량 82종.
- 주차 안내원·요리사·바리스타·계산원·청소원·주유 직원·여행객·경찰의 인물 8종. 몸체와 휴대 장비는 별도 입력/모델로 둔다.
- 소품: TRELLIS 원본, 정리된 `.blend/.glb/.fbx`, 2K 재질, 검증 기록과 다각도 미리보기.
- 인물: TRELLIS 몸체, 스킨 웨이트·사람 본, Idle/Walk/Run/Attack/Hit/Death 및 역할에 필요한 동작. `.blend/.glb/.fbx`, 애니메이션 미리보기와 새 임포트 확인.
- 이전 이미지·Blender v4·게임 씬은 보존한다. 이 제작 작업에서 Unity 런타임 씬 설치나 300초 새 영상 제작은 요구하지 않았다.
- 이동 카트는 제외. 선택적 장식 제안 6종은 이번 확정 제작 범위에 추가하지 않는다.

## 저장값

원본 `앱/.state/settings.json`을 `saved-settings.json`으로 보존한다. 해상도1536, 텍스처2048, 최종15000삼각형, 중간300000면, 시드12345, 형태12스텝, 텍스처25스텝, tiled decoder=true, keep_models_loaded=false, low_vram=false, remove_floor=true, quality_retry=true, stage_quality=true, 파일 사이60초 휴식을 유지한다. 과거 경로에 덮어쓰지 않도록 입력/출력 경로와 작업 전용 포트만 변경한다.

시드12345는 기본값이다. 재시도는 설치된 기존 자동화의 결정적 파생 시드 정책(두 번째 메시117074, 세 번째 메시221803)을 그대로 따른다. 각 실제 시드와 시도 수는 변경하지 않은 원장에 남는다.

일반 바닥 제거는 명백한 과대 받침 조각에만 적용하는 기존 자동화의 조건을 따른다. 실제 도로·바닥·받침대의 본체를 제거한 결과는 통과시키지 않는다. 그림 크기는 게임 월드 크기가 아니며 v4의 차량 확대 기준·인물 대비 크기는 후속 조립 시 유지한다.

## 실행과 품질

기존 자동화 엔진을 사용하고, 기존에 제작/검증된 독립 UV 수학 경로(`tools/run-trellis-uv-math.py`)를 작업 포트8189에서 사용한다. 이는 기존 NVIDIA UV 구현의 특정 의존 문제를 피하는 경로이며 모든 외부 구성 요소에 대한 포괄적 상업용 보증이 아니다.

기존 형태→고밀도 재질→감량본 비교의 순서와 최대 메시3회/재질총3회/Blender감량2회 정책을 유지한다. 저장소 지시에 따라 새 보조 에이전트를 띄우지 않고 주 에이전트가 생성된 다각도 렌더를 보고 같은 JSON 판정 형식으로 평가한다. 자동화가 기다리는 것은 사용자 승인 요청이 아닌 주 에이전트의 실제 검토 단계다. 허위 pass를 기록하거나 검토를 생략하지 않는다.

F08 의자를 먼저 생성해 전체 경로를 확인한 뒤 나머지를 이어간다. GPU 생성 요청은 한 건씩 처리한다. CPU만 쓰는 Blender 검토/보정은 자원 제한 안에서 GPU 계산과 겹쳐 진행할 수 있으며, 추가 GPU 요청은 기존 요청이 끝난 뒤에만 제출한다. 실패는 원인을 기록하고 출력물을 보존한다. 새로운 입력은 ImageGen으로 단일 물체/장비 없는 리깅 자세의 인물을 제작한다. 기존 69종은 다시 그리지 않는다.

TRELLIS가 형태·재질 단계를 담당하므로 Blender의 수동 graybox/형태 제작 단계는 해당 생성 단계의 검토로 대체한다. Blender는 메시 정리, 피벗, 리깅, 재질 보존, 애니메이션 및 내보내기 검증을 담당한다. 단순 블록이나 막대 인물을 완성 모델로 대체하지 않는다.
