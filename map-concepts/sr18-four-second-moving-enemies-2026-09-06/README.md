## 교차부 보너스 자리 교환

### 2026-09-07 — 가운데 교차부 벽 하나 추가 이동

사용자가 다시 표시한 177초 식별 슬롯의 BonusWall만 왼쪽으로 ¼모듈(2.8125유닛) 더 이동했다. X는 `118.24978187 → 115.43728187`, Z는 `-77.7511` 그대로이며 첫 고가 상부 평지에 유지된다. 왼쪽 161초 벽과 위쪽 269초 벽, 모든 적·기믹·총수량은 직전 상태 그대로다.

`py -3.11 -X utf8 tools/draw_sr18_four_second_moving_enemies.py --nudge-center-left`로 재현한다. 177초 이벤트 외의 전체 이벤트가 변경되지 않았는지 검사하고 확대도·전체 맵을 확인했다. 이전 이미지와 데이터는 보존했으며 실제 Unity 씬은 변경하지 않았다.

### 후속 미세 이동 — 아래쪽 가로 다리의 두 벽

사용자 표시 대상은 위쪽 ②가 아니라 **첫 고가(S09)의 161초·177초 BonusWall**이다. 이 둘만 도면의 왼쪽, 즉 월드 X 음의 방향으로 ¼모듈(2.8125유닛) 이동했다. Z와 상부 다리 소속은 유지했고, 위쪽 269초 벽과 모든 적·기믹·다른 벽은 변경하지 않았다.

| 식별 슬롯 | 이전 X | 변경 X | Z |
| --- | ---: | ---: | ---: |
| 161초 벽 | -16.91335 | -19.72585 | -77.7511 |
| 177초 벽 | 121.06228 | 118.24978 | -77.7511 |

총 적 25·BonusWall 25·기믹 24와 움직이는 적 수는 같다. 슬롯 시간은 식별용 목표값으로 유지하되, 좌표 이동에 따른 균등 이동 환산 시간은 최신 JSON의 `geometry_time`에 별도 기록했다. 실제 통과 시각이 정확히 종전과 같다는 의미는 아니다. 첫 벽이 경사 끝에 가까워져 검토 표시를 추가했으며 실제 적용 시 벽의 크기와 바닥 여유를 확인한다.

재현: `py -3.11 -X utf8 tools/draw_sr18_four_second_moving_enemies.py --nudge-left`. 두 X 좌표만 이동했는지, 위쪽 269초를 포함한 나머지 이벤트가 그대로인지와 총수량을 검사했다. 최종 전체 맵과 이동 확대도를 확인했다. **실제 Unity 씬은 수정하지 않았다.** 아래는 선행 교환 기록이다.

사용자가 표시한 두 적 지점은 전투 대신 BonusWall 지점으로 바꿨다. 새 벽을 추가하지 않고 같은 진행 구간의 가장 가까운 기존 벽과 교환했다.

| 위치 | 교차부 변경 | 기존 벽 자리 변경 |
| --- | --- | --- |
| 첫 고가 상부 진행선 | 2:41 적 → BonusWall | 2:45 BonusWall → 기본 적 |
| 두 번째 고가 진행선 | 4:29 적 → BonusWall | 4:33 BonusWall → 기본 적 |

선행 교환 당시 총 적 25명·BonusWall 25개·기믹 24개, 기본 적 15·왕복 5·매복 5는 그대로였다. 네 지점의 종류만 교환하고 시간·좌표·경사 검토 표시를 보존한 뒤, 위 후속 요청에서 두 X 좌표를 미세 이동했다. 두 번째 고가 교차부 표식은 경사 경계 인근이므로 실제 적용 시 윗길 높이와 발동 영역을 검증해야 한다. 아래층 길로 잘못 옮기는 것은 의도한 변경이 아니다.

재현: `py -3.11 -X utf8 tools/draw_sr18_four_second_moving_enemies.py --crossing-bonuses`. 코드에서 변경 지점이 161/165/269/273초 네 곳뿐인지, 전체 수량·행동 역할 수가 같은지, 다른 시간·좌표가 보존되는지 검사했다. 최신 전체 맵과 두 지점 확대도를 확인했다. **실제 Unity 씬은 변경하지 않았다.**

## 리듬과 역할

0–5초는 이동만 한다. 5초 첫 약한 적 → 9초 BonusWall → 13초 기믹 → 17초 다음 적으로 이어진다. **전체 조우는 4초 간격**이다. 기본 순환에서는 같은 종류끼리 12초 간격이지만, 위의 교차부 자리 교환은 종류 순서의 예외다. 종류별로 각각 4초마다 나오는 구조가 아니다.

300초 목표 그림에는 적 25개 칸, 고정 BonusWall 25개 칸, 기믹 판단 24개 칸이 있다. 적 칸은 기본 15·왕복 5·전방 매복 사격 5로 예시 배분했다. 움직이는 적을 별도 조우로 더해 빈도를 높이지 않는다. 이는 그림의 배분이며 최종 적 수·능력치·스테이지 난이도 확정값은 아니다.

## 왕복 이동 적

- 같은 적 한 마리가 좁은 통로의 앞·뒤 지점 사이를 왕복한다. 여러 마리를 가로로 놓지 않는다.
- 지정 구역에 진입하면 이동을 시작한다. 기존 칼/그물 등 캐릭터와 왕복 이벤트를 재사용하는 방향이다.
- 자기 전투 칸에 머물며 코너·경사·다음 보너스·기믹 칸에 침범하지 않는다. 데이터의 앞뒤 4유닛은 범위 후보로, 실제 속도와 함께 검증해야 한다.
- 첫 두 적은 기본형으로 남기고 새 행동은 단순 전투 구간에서 소개한다.

## 전방 매복 → 등장 → 원거리 사격 적

1. 적은 플레이어보다 충분히 앞쪽의 기존 상점 뒤/시야 밖 대기 위치에 있다.
2. 플레이어가 연결된 구역에 들어오면 그 **전방 위치**에서 길 쪽으로 나타난다.
3. 등장과 발사 준비를 읽을 틈을 준 뒤 거리를 둔 상태에서 사격한다.

**플레이어 바로 옆이나 등 뒤에서 생성되는 연출은 금지한다.** 기존 경비원·뚱보처럼 투사체가 준비된 적을 활용한다. 대기 공간은 기존 소품과 안벽에서 찾아야 하며, 그림의 사각형은 새 건물이나 갈래길이 아니다. 이동 경로가 다른 길·상점 몸체·물과 충돌하지 않는지 실제 맵에서 확인한다.

그림에서는 시장 직선에만 매복 후보를 두고 고가에서는 제외했다. **4초의 기본 배치 간격과 실제 매복 발동·이동·발사 시점은 다르다.** 직전 기믹 대응과 첫 발이 겹치거나 보너스 선택을 가리지 않도록 따로 조율한다. 데이터의 발동 거리 후보는 확정 밸런스 값이 아니다.

## 현재 기능과 추가 구현

- 기존 `EnemyEventController`에는 앞뒤 왕복, 지정 위치 이동 후 공격, 단발 사격이 각각 있다. `EnemyEventActivationSpot`은 연결된 이벤트를 활성화한다.
- **이동 후 공격은 도착 후 공격 반복으로 전환하며 자동으로 Shoot에 이어지지 않는다.** 시야 밖 대기/표시 전환 → 이동 → 사격을 한 적의 연속 행동으로 만드는 연결은 추가 구현이 필요하다.
- 이번 작업은 해당 동작을 기획서와 이미지에 추가한 것이며 런타임 컨트롤러·프리팹·씬을 수정하지 않았다.
