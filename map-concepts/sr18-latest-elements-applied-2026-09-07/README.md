## 현재 구성

- 적 25명: 기본 15, 앞뒤 왕복 5, 전방 매복 사격 5. 한 지점에 한 마리.
- 고정 BonusWall 25개: Normal 18, Rare 6, Unique 1. 한 지점에 한 제단.
- 기믹 24개: 양동이 9, 가로등 8, 구멍 7. 기존 프리팹만 사용하며 가로등 묶음은 한 개만 활성화했다.
- 적 발동 스팟 25개, 독립 이동 목표 10개. Props는 기존 666 + 발동 스팟 25 + 기믹 24 = 715개.
- 길 230개, 점포 306개, 안벽 306개, 코너 15개, 경사 전환 8개와 기존 물·장식은 보존했다. 맵1/맵2와 공유 프리팹·워크북은 변경하지 않았다.

입력은 [가운데 벽 추가 이동까지 반영한 JSON](../sr18-four-second-moving-enemies-2026-09-06/image-plan-center-left-2026-09-07.json)이다. 첫 5초 비움·4초마다 한 종류를 만나는 74개 슬롯을 사용했다. 161/177/269초 식별 슬롯의 벽은 각각 X `-19.725851 / 115.437282 / 312.827708`을 유지한다. 269초 벽은 두 번째 고가의 내리막에 맞춰 높이와 기울기를 조정했다.

코너 중심에서 8유닛 이내인 배치만 같은 구간 안쪽으로 보정했다. 기믹은 좌우 0.8유닛을 교대로 사용하며 경사에는 구멍 대신 양동이를 사용한다. 실제 좌표·방향·크기·보정은 [적용 기록](placement-report.json)을 따른다.

## 행동

왕복 적은 중심에서 앞뒤 4유닛, 총 8유닛을 속도 2.5로 이동한다. 경사와 코너를 넘지 않는다.

매복 적은 경비원/뚱보를 사용한다. 별도의 상점 뒤 공간을 새로 만들지 않고 **전방 통로에서 숨김 대기 → 등장 → 2.5유닛 이동 → 사격**으로 구현했다. 발동선에서 대기점까지 32.5유닛, 이동 속도 4, 도착 뒤 투척 준비 0.7초, 투사체 속도 14다. 등장 전 렌더러·체력 Canvas·콜라이더를 숨기며 오브젝트 자체는 활성 상태로 유지한다. 새 이벤트 `AmbushMoveThenShoot = 6`은 Inspector와 맵툴에서 선택한다. 기존 enum 번호는 유지했다.

기존 적 처치 BonusWall 드롭 규칙은 유지했다. **고정 25개가 플레이 중 만나는 모든 보너스의 총합은 아니다.**

## 검증·복구

추가 SR18 검사와 실제 Play 검증을 완료했다. 양동이 원본의 비활성 상태를 씬 인스턴스에서 보정했고 24개 기믹 충돌체, 25개 발동 스팟, 10명 이동, 매복 투사체 5개 발사·정지·초기화를 확인했다. 최신 설정은 [엑셀 배치 설정](../../docs/noryangjin-encounter-workbook.md)을 따른다. [검증 이력](verification.md)의 대기 기록은 이전 상태다. 4초/300초는 거리 환산 목표이며 실제 처치·회전 시간을 포함한 전체 밸런스 완주는 별도다.

`tools/apply-sr18-latest-elements.cs`는 이전 배치의 이름·위치·크기·방향을 확인하고, 열린 SR18을 사본으로 백업한 후 소유한 이전 배치만 교체한다. 이미 적용 기록이 있거나 기존 배치가 달라지면 재실행을 거부한다. 이후에는 맵툴의 일반 편집 기능을 사용한다.

백업 경로는 [placement-report.json](placement-report.json)의 `backup` 필드에 있다. 양동이 고정 Rigidbody 설정 전 사본도 `tmp/backups/sr18-latest-elements-2026-09-07/bucket-physics-*`에 남겼다. 복구 시 현재 씬을 먼저 새 사본으로 보존하고 Unity에서 백업을 열어 확인한 후 SR18에만 저장한다. 전체 작업 트리를 되돌리지 않는다.
