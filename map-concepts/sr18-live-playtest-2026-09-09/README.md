# SR18 실제 게임 루프 검증 — 2026-09-09

2026-09-10 후속: 아래 네 결함을 수정했다. 현재 상태는 [수정·재검증 기록](../sr18-runtime-fixes-2026-09-10/README.md)을 따른다. 이 문서는 수정 전 관측을 보존한다.

판정: **추가 수정 필요**. 개별 함수/배치 검사가 통과했어도 실제 연속 플레이에서는 공통 사격 오류와 초반 읽기 어려운 구간이 확인됐다. 이번 요청은 플레이 검증이므로 원본 게임 코드·씬·엑셀은 수정하지 않았다.

## 방식

Unity의 실제 시작 처리와 `PlayerMove`에 조작 입력만 넣었다. Transform 순간이동, 적/기믹 충돌 비활성화, 발사/이동 함수의 수동 시간 진행 없이 실제 Update·FixedUpdate·충돌·피격·보너스 처리를 실행했다. 사용자가 다른 앱을 조작 중이어서 마우스/키보드 점유는 중단하고 Unity 내부 입력 드라이버를 사용했다.

- 일반 실행 1: 체력100·공격력50·속도8, 중앙 진행. 약40초 후 구멍에서 사망, 적3명 처치, 바구니 사격 금지 약3초 확인.
- 일반 실행 2: 동일 기본 수치, 좌우 선택/기믹 회피 입력. 첫 선택 보너스 획득 후 기존 가로등 구간에서 100→50→0 연속 피격으로 약17초에 사망.
- 후반 검사: 시작 후 체력만 테스트용10,000,000으로 올렸다. 공격력·속도·충돌·보너스 처리는 유지하고 TimeScale1로 진행했다. **이 실행은 성장 밸런스나 정상 체력 완주의 증거가 아니다.** HP 보너스와 TungTung 체력도 임시 체력의 영향을 받는다.

## 확인한 문제

### 1. 탄환 재사용 손상 → 실제 발사 오류

연속 진행 중 `WeaponScript.ShootBullet()` 175행에서 NullReferenceException이 발생하여 Unity Error Pause가 걸렸다. 실행 도중 물 탄환 풀의 등록 오브젝트2개가 `GFX`와 `BulletScript`를 잃은 빈 루트인 것을 확인했다. 정상 프리팹에는 스크립트가 존재했다.

격리 재현에서 같은 BulletScript에 반환을 두 번 요청하면 첫 반환은 정상이고 두 번째 반환 후 풀의 루트가 자식을 잃었다. 원인은 `BulletScript.ReturnToPool → BulletPooler.Return(root) → SetActive(false) → BulletScript.OnDisable`에서 `projectileRoot`가 null이 되는 흐름이다. 중복 반환은 `GetProjectileTransform()`의 fallback으로 GFX를 반환하고, 풀은 미등록 오브젝트로 판단해 해당 자식을 분리·삭제한다. 나중에 빈 루트를 꺼내면 WeaponScript가 BulletScript를 찾지 못한다.

필요 수정: 반환을 한 번만 허용하고, 풀의 정식 루트/대여 상태를 유지·검증할 것. 재현: `tools/reproduce-sr18-double-projectile-return.cs`. null 검사로 발사만 건너뛰는 것은 근본 해결이 아니다.

### 2. 첫 교차 고가도로가 카메라를 가림

첫 보너스/바구니 진입 주변에서 상부 다리 바닥과 기둥이 플레이어와 길 대부분을 가렸다. 충돌체 배치가 맞아도 판단에 필요한 화면이 보이지 않는다. 필요 수정은 시야를 가리는 구조물의 카메라 대응이며, 이번 검증에서 임의 삭제하지 않았다.

### 3. 엑셀 밖에 남아 있는 기존 가로등4개

`Noryangjin_MapTool/Props/Prop_Lights_X-49_Z-139` 아래의 Light1/Light2 각2개가 활성 상태다. 각각 피해50이며 초반 Z 약−31..−20에 걸쳐 있다. 전체씬에는 ObstacleStats70개, 활성46개가 있었다. 새 SR18 지점만 세던 검사(활성42개)가 이4개를 놓쳤다.

필요 결정: 기존 가로등을 장식으로 유지할지, 새 조우 배치표에 편입할지 정한 뒤 수정. 신규 `기믹 배치`만 바꿔서는 이 피해를 조정할 수 없다.

### 4. 출구 처리 누락 여부

씬에 `GameEndTriggerTag` 오브젝트가 없다. 실제 플레이어가 출구 Z338.5를 지나 Z354.045까지 물 위로 계속 이동했고, 클리어 전환 없이 `isGameRunning=true`였다. 여기서 테스트 감시기가 강제로 멈췄다. 필요 수정은 실제 출구의 완료 처리와 길 밖 전진 방지다.
