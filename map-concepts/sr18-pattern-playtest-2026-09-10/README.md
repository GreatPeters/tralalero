# SR18 정상 체력 플레이와 기믹 패턴 검토 — 2026-09-10

후속: 사용자의 개선 요청으로 [초반 기믹·가로등·HUD 개선](../sr18-opening-rhythm-2026-09-10/README.md)을 적용했다. 아래 내용은 적용 전 관측과 제안을 보존한다.

판정: **초반 기믹의 대응 방식이 반복되고, 새 가로등의 전도 후 피해와 체력 막대 표시를 후속 확인·수정할 필요가 있다.** 이번에는 게임 코드·씬·Data.xlsx를 변경하지 않았다. 아래 개선안은 미적용 제안이다.

## 테스트 조건과 범위

- `map2`, 현재 SR18 씬. 시작 체력100·공격력50·전진속도8·TimeScale1. 체력 보강, 무적, 충돌 해제, 순간이동 없이 실제 시작 처리·Update/FixedUpdate·충돌·보너스·사망 처리를 실행했다.
- 마우스/키보드를 점유하는 수동 플레이가 아니라 기존 `PlayerMove`에 좌우 입력을 넣는 에디터 드라이버를 사용하고 실제 GameView를 검토했다. 보너스/기믹의 씬 좌표를 읽는 드라이버이므로 인간의 시각 반응속도나 첫 플레이 난이도를 인증하지 않는다.
- 보너스는 매 실행 무작위다. 시드를 고정하지 않았으므로 실행 간 생존시간 차이를 조작 전략의 효과만으로 해석하지 않는다. 정상 보너스로 증가한 HP와 지원군은 유지했다.
- 가장 오래 진행한 실행도 약98초다. **정상 난이도 완주와 후반 플레이는 이번에도 미검증이다.** 이전 체력 보강 완주와 [런타임 수정 검증](../sr18-runtime-fixes-2026-09-10/README.md)의 범위는 그대로 유지한다. 고속도로 자동 전환은 미구현이다.

## 반복감의 근거

1. **서로 다른 외형이 비슷한 이동 문제를 낸다.** 현재24지점은 Bucket9묶음/27개, Light8개, Hole7개다. 24지점 중23개가 `양동이→가로등→구멍` 반복 순서와 일치하고 G15만 구멍 대신 양동이다. 전체 수량·순서는 현재 씬 스냅샷으로 확인했으며, 후반의 체감까지 플레이한 것은 아니다.
2. **양동이3개가 하나의 판단으로 끝난다.** 세 개가 같은 쪽 차선에 길 방향2.5유닛 간격으로 이어져, 반대편을 유지하면 묶음 전체를 피한다. 물체 수 증가가 조작 변화를 만들지는 않는다.
3. **공격 금지가 전투와 분리된다.** 실행1의 약15~18초에 `canShoot=false`가 관측됐지만, 해당 세 샘플에서 첫 적은 이미 죽었고 다른 적은 아직 대기 상태였다. 불리한 상태에 대응할 전투가 없는 첫 양동이 구간이다. 이 관측을 모든 양동이 구간으로 일반화하지 않는다.
4. **기본 리듬의 역할 변화가 적다.** 기존 목표는 적→보너스→기믹의4초 배치 칸이며 동일 종류는12초마다 반복된다. 코너 대응 공간 조정 이후 실제 접촉 시각은 다르다. 현재 구조는 반복 도전에 필요한 새 판단보다 같은 순서를 익히는 비중이 크다는 것이 이번 검토의 판단이다.

## 새 가로등: 쓰러진 뒤에도 회피 차선을 덮는 피해 판정

이 항목은 앞서 장식으로 전환한 기존 가로등4개와 별개인 **`SR18_L_G05_T061_Light`**다.

- 실행2는 같은 구간에서 HP72.81→22.81, 실행3은44.92→0이 됐다. 당시 적은 다음 대기 적을 제외하고 모두 사망 상태였고, 실제 화면에서 가로등이 길을 가로질러 누운 모습을 확인했다.
- `ObstacleStats.ToppleLampOnly()`는0.5초 동안88도 회전하지만 피해 트리거를 끄지 않는다. `OnTriggerEnter`의 Light 분기는 전도 여부와 무관하게 피해를 준다.
- 별도의 **동작 단독 검사**에서 현재 씬의 이 가로등에 전도 함수를 직접 호출했다. 게임은 시작하지 않았으며 이 검사는 생존시간 표에 포함하지 않는다. 전도 전 충돌 중심/반폭은 `(125.93,3.37,3.25)/(0.83,3.30,0.85)`, 전도 후는 `(121.92,.92,3.25)/(3.32,.94,.85)`다. 전도 후에도 `enabled=true`, `isTrigger=true`, 피해50이었다.
- 처음 비어 있던 쪽으로 피하더라도 자동 사격으로 가로등이 쓰러지면 위험 영역이 그쪽으로 이동한다. 기존 드라이버가 기믹 루트 위치만 읽는 한계도 드러났다. 이는 인간에게 무조건 회피 불가능하다는 증거는 아니다.
- 개선 시 가로등의 역할을 분명히 해야 한다. ‘쏴서 길을 여는 물체’라면 전도 후 피해를 없애고 성공을 보여주는 방향이 자연스럽다. ‘넘어지는 것을 피하는 물체’라면 낙하 방향과 안전 공간을 미리 읽을 수 있게 해야 한다. 아직 어느 쪽도 적용하지 않았다.

## 체력 HUD 관측

실제 화면의 체력 숫자는73/100 또는23/100으로 줄지만 빨간 막대는 가득 차 있다. 현재 SR18 `HealthFill`의 Image 타입은 `Sliced`이고, `PlayerStatusHud.SetHealth`는 `fillAmount`를 변경한다. 빌더는 `Filled`를 지정하므로 현재 씬 설정과 맞지 않는다. UI 타입 보정과 실제 피격 후 화면 검증을 후속 작업으로 남긴다. 이번 테스트에서 수정하지 않았다.

## 권장하는 첫 개선 실험 — 미적용

우선 처음60~90초에서 **회피·사격으로 길 열기·보상 회수**가 번갈아 필요하도록 소수 지점을 바꾸는 것이 좋다. 전체24지점에 새 물체를 더하기 전에 비교 플레이할 작은 구간을 만든다.

- 양동이: 짧은 회피 구간 뒤에 약한 적을 배치해 피했을 때 공격을 유지한 이점이 드러나게 한다. 공격 불가와 즉사 구멍을 한꺼번에 겹치지 않는다.
- 가로등: 파괴 성공으로 열리는 경로와 돌아가는 경로를 구분해 정면 조준/회피 중 선택을 만든다. 먼저 전도 후 피해 규칙을 정한다.
- 구멍: 통과 가능한 공간을 충분히 보여주고, 위험 가장자리의 추가 보상은 선택 사항으로 둔다. 영구 체력 성장이 생존거리를 늘리는 게임에서 즉사 장애물을 성장 벽의 주된 원인으로 쓰지 않는다.
- 리듬: 같은 순서와 간격의 반복 안에서도 `학습→짧은 조합→보상/호흡`의 차이를 만든다. 기존4초 목표를 바꾸는 일은 별도 디자인 결정이다.
