# 뚱보 양손 투척 재수정

> 이후 사용자가 떨림과 선행 발사를 지적했다. 이 버전의 동작 제어와 첫 프레임 숨김은 [단일 포즈 제어 및 투척 동기화 수정](../synced-crate-throw-2026-09-20/README.md)으로 대체되었다. 아래 내용은 이전 시도의 기록이다.

사용자가 거절한 한 손 부착 방식과 몸통 관통을 수정했다. 상자를 몸 앞의 독립된 기준점에 두고 양손이 같은 상자의 양쪽을 잡는다. 소스 FatMan 프리팹과 SR18의 6개 배치에 적용했다. 앞선 배 방향 수정은 유지했다.

## 동작

- 상자는 손 본의 자식이 아닌 Animator 모델의 독립 자식이다. 가로 .76 / 높이 .28 / 깊이 .36 모델 단위로 얕게 맞췄다. 현재 배치에서 약 1.60 × .59 × .76m다.
- `FatManCratePose`가 얼굴/몸통을 움직이는 기존 애니메이션은 유지하면서, 배 앞에 놓인 상자의 양쪽 손잡이에 두 팔을 맞춘다. 손목만이 아니라 실제 손 메시에서 측정한 손바닥 중심을 기준으로 한다.
- 준비 동작은 상자를 배 안으로 당기지 않는다. 놓는 순간에는 양손 보정을 풀고 원래 후속 동작으로 돌아간다. 다음 투척에서 다시 양손으로 잡는다.
- `EnemyScript_space`는 이 상자의 방향을 그대로 유지해 발사한다. 기존 Arrow2의 +X 방향 보정은 가드에게만 적용돼 상자가 발사 순간 90도 돌아가지 않는다.
- 새로 켜진 Animator가 정착하는 첫 프레임에는 상자를 숨기고, 양손 자세가 안정된 다음 표시한다. 화면 밖에서 애니메이션 갱신이 중단돼도 팔 보정이 누적되지 않도록 원래 회전을 복원한 뒤 평가한다.
- 기존 제자리 대기, 약 5초 접근 기준, .62초 발사 준비와 2.8초 반복 주기는 유지한다.

## 검증

- 두 C# 프로젝트 빌드 성공, agent harness 검증 성공. 런타임 빌드의 기존 ithappy `SplineSpeed.m_LastIndex` 미할당 경고 외 오류 없음.
- `FatManTwoHandPoseTests` 4개 통과: 4방향 × 대기/투척 클립 × 32시점, 총 256개 포즈에서 양손 접촉과 실제 스킨 몸통/머리 정점의 상자 내부 침범 여부를 확인했다.
- `CombatRouteFeedbackTests` 13개 통과.
- 실제 Play Mode 210프레임/30fps, 3회 발사: `play-ready/report.json`.
- 보이는 잡기 프레임 76개에서 왼손 최대 오차 .000024m, 오른손 .000022m. 잡는 동안과 발사 순간 모두 몸통/머리 정점 침범 0개. 상자와 겹치는 높이·가로 범위의 몸통 앞 표면 간격은 최소 약 .080m였다.
- 발사 방향 변화 0°, 캐릭터 위치 이동 0m. 정면과 측면을 실제 렌더링으로 촬영하고 영상 재생도 Chrome에서 확인했다. 수치는 이 프리팹과 촬영한 동작에 대한 결과이며 모든 향후 모델 수정의 보증이 아니다.
- Unity는 저장된 SR18 Edit Mode로 복구했다. 실제 휴대폰 실행은 하지 않았다.

## 영상과 도구

- [정면·측면 연속 동작](http://127.0.0.1:6753/two-hand-crate/) — 기존 로컬 서버가 실행 중일 때 사용.
- 원본 사본: `tmp/image-previews/two-hand-crate-2026-09-20/`.
- `tools/install-two-hand-crate.cs`: source prefab + 6개 배치 설치, 실행 전 사본은 `before/`.
- `tools/record-two-hand-crate.cs`: 실제 애니메이션/물리/반복 발사와 메시 접촉을 기록한다.
- `tools/build-two-hand-crate-gallery.py`: 접촉·침범 검사에 실패하면 영상 갤러리 생성을 중단한다. 210개 원본 프레임을 정면·측면 나란히 인코딩한다.

`prototype*`는 공간/팔 길이/손바닥 위치 조사이고 `play-v1`, `play-v2`, `play-final`, `play-diagnostics`는 초기에 발견한 재활성화 첫 프레임 문제를 보존한 기록이다. 전달본은 `play-ready`다. 최초 포즈 미리보기에서 스킨 렌더링이 같은 Editor 프레임의 본 변경을 늦게 반영했으므로, 정적 조사에는 보정된 BakeMesh를 사용했고 완료 판정에는 실제 Play Mode 연속 렌더를 사용했다.
