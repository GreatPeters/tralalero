## 실제 구축 경로

- Blender Python의 회전/윤곽 압출/베벨, 구체·큐브, 고정 튜브 곡선으로 메시 제작. 고리·열쇠·발자국은 윤곽 압출, 결정은 단순 단면 연결, 캡슐은 회전체를 두 부품으로 분리한다.
- 부적은 몇 개의 평면을 힌지로 펼친다. 버클과 매듭의 끈은 고정 메시로 처리하고 천/로프 시뮬레이션을 쓰지 않는다. 결정을 실제 굴절 재질로 만들 필요는 없다.
- 하트/검은 기존 UI 아이콘 또는 간단한 윤곽 압출 메시를 사용한다. 하트 PNG는 `Assets/ShooterSurvival/UI/CoastalEnamel/Heart.png`에 존재한다. 원본 이미지의 입체감까지 파일 하나로 구현되어 있다는 뜻은 아니다.
- `Assets/ShooterSurvival/Scripts/Walls/BonusRewardCue.cs`와 `Assets/ShooterSurvival/Editor/HarborBonusPresentationInstaller.cs`를 읽어 획득 훅과 기존 파티클 제작 경로를 확인했다. 현재 cue는 플레이어 원점 + 1.65m에서 효과를 생성하므로 신발 앵커로 이동하는 효과는 새로 구현해야 한다.
- 기존 WallScript의 보상/획득 처리와 분리한 시각 부품을 만들고, 기존 ParticleSystem 재질을 활용한 작은 발광·짧은 궤적으로 연결한다. 모든 부품을 하나의 시각 루트로 묶어 동일한 프리팹을 세 씬에서 사용한다.
- 런타임 드롭과 미리 배치된 보너스는 적용 경로를 각각 확인해야 한다. 한 씬의 배치물만 바꾸고 전체가 교체됐다고 판단하지 않는다.
- 본격 제작 시 선택 표시·1회 획득·풀링/재시작 초기화·세 씬 카메라 가독성·신발 앵커와 입자 비용을 Unity에서 검증한다. 이번 이미지는 제작 설계이며 제작 완료·성능 검증 결과가 아니다.
- 난이도는 01/04/05/06/08이 비교적 단순하며, 02/03/07/09/10은 분리 부품 또는 순차 동작이 추가된다. 모두 외부 생성 모델 서비스에 의존하지 않고 제작할 수 있는 구성으로 제한했다.
- 08의 주사위는 외형이다. 표시된 고정 보너스를 주며 무작위 지급 기능을 추가하는 제안이 아니다.
